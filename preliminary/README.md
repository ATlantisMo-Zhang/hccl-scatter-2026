# 初赛：Scatter（AICPU + TS）

初赛阶段的完整工程。赛题为在 AICPU + TS 引擎上实现 2×8 拓扑（P=16）的 Scatter 集合通信算子，3 个性能测试点（38μs 小消息 / 两个大消息点）。

最终提交（255304）成绩：**38μs / 1.13ms / 895μs**，两个大点较初版 Push 基线快 22.6% / 22.2%。

## 方案演进

| 版本 | 机制 | 说明 |
|---|---|---|
| V1–V7 | 中转去除、整包暂存、分轮并行、分批、按槽复用 | 通用路径打磨 |
| V8 | 小消息四叉控制树 | 小消息延迟优化 |
| V9/V10 | 部分远端中继、小树+中继组合 | 中继路线探索 |
| 252193 | 一段 Push | 38 / 1460 / 1160 μs |
| 253741 | 两段 Push 流水 | 38 / 1460 / 1150 μs，无明显净收益，放弃 |
| **255304** | **固定 1/4 远端分流（tails-first）** | **38 / 1130 / 895 μs** |

## 最终方案：固定 1/4 远端分流

2×8 拓扑下 root 有 7 条机内链和 8 个异机 rank。瓶颈在 root 的直接跨机出口（Clos）。

核心设计：

1. root 把每个异机 rank 数据中**末尾 1/4**（`(count/4)*4` 个 float）先发给同机 7 个 helper（其中一个 helper 承担 2 份尾片）
2. helper 收到后立即启动转发 worker，把尾片中继给对应异机 rank；同时完成自己那份数据的 Copy——**转发不依赖自身 Copy 完成**
3. 异机 rank 从 root 直收前 3/4、从 helper 收尾 1/4，两份数据并行到达

效果：root 直接跨机量从 8B 降到约 6B，总网络量反而从 15B 增到约 17B、任务数从 181 增到 291——**总量增加却快 22%**，证明瓶颈在最忙链路（root 跨机出口）而不是总工作量。

准入条件（保守回退）：P=16、B≥1MiB、`B+2F` 不超过全部 rank 最小 CCL 容量，不满足则回退一段 Push 或旧分支。
